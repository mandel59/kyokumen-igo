# AI 評価関数のチューニング記録（2026-10-20）

調整前の AI（`legacy`）に対する最終版（`tuned`）の成績は、12,000 局中 11,593 勝、勝率 96.6% でした。Rust で自己対局と重みの探索を行い、採用した重みと勢力評価をブラウザの JavaScript に反映しました。実装はコミット `4c5375f` に含まれます。

この文書は、Claude のセッション の実行コマンド・出力と、保存されていた探索ログをもとに 2026-10-21 に整理した作業記録です。以下の数値は当時の測定結果であり、文書化のために探索をやり直した結果ではありません。

## 目的と実装

目的は、既存の「合法手を採点して 1 手先だけを選ぶ」AI の評価関数を調整し、能力を伸ばすことでした。木探索や学習済みモデルは追加していません。

大量の対局を短時間で行うため、盤のグラフ生成、合法手・取り・自殺手・位置的スーパーコウ・面積得点、AI の評価を Rust に移植しました。外部クレートは使っていません。交点 ID と隣接点の順序も JS 版に合わせています。

実行環境は Windows、Rust / Cargo 1.99、利用可能な論理プロセッサ数は 16 でした。対局は `available_parallelism()` で得た並列数で実行します。乱数には SplitMix64、候補の正規分布からの抽出には Box–Muller 法を使います。

移植直後、調整前の重みで作った 600 局面について、乱数の加点を 0 にしたときの選択手が JS と Rust で 600 / 600 一致しました。JS の重みを注入可能にする変更のあとにも同じ確認を行っています。

## 試した評価要素

既存の取り・アタリの石の救出や捕獲・呼吸点・隣接する石などの評価に、次の 2 要素を加えて探索しました。

- **勢力（`territory`）**：各石からグラフ距離 1・2・3 の点に、それぞれ 4・2・1 の勢力を加算します。黒を正、白を負とし、空点での符号からどちらの地になりそうかを見積もります。着手点が空点でなくなる分と、周囲の空点の符号が着手側に変化する分を評価します。取りによる勢力の変化まで再計算するものではありません。
- **新しく掛けるアタリの数（試作時の `atari`）**：着手後、呼吸点が 1 つになる隣接した敵の連の数を評価します。検証後に削除しました。既存のアタリの石を助ける・取る評価は残っています。

## 探索条件

当時の実行コマンドは次のとおりです。`tools/ai-tuner/` で、アタリ評価を含む試作版を実行しています。

```sh
cargo build --release
./target/release/ai-tuner tune --generations 60 --population 32 --elite 8 --games 64 --seed 1 > tune-full.out 2> tune-full.log
```

探索は 2026-10-20 の 23:38 頃から 23:44 頃（日本時間）まで、約 6 分 17 秒でした。世代番号は 0〜59 です。

| 条件 | 設定 |
| --- | --- |
| 探索法 | 交差エントロピー法 |
| 初期値 | `Params::legacy()` |
| 世代数 / 候補数 / 上位候補数 | 60 / 32 / 8 |
| 探索する重み | 13 個（既存 11 個 + `atari` + `territory`） |
| 固定する重み | `capture = 10`、`noise = 0.7` |
| 盤 | 球面 n=3・4・5（56・98・152 点）、トーラス 7×7・9×9・11×11 |
| コミ | 全対局で 6.5 目 |
| 各候補の評価 | `legacy` と champion それぞれに、各盤 64 局。両相手への勝率の平均 |
| 先後 | 対局番号の偶奇で交代し、各盤で半数ずつ |
| champion の更新確認 | 上位 8 候補の平均を、champion と legacy それぞれに各盤 128 局で評価 |
| 昇格条件 | champion への勝率が 53% を超える |
| 対局の打ち切り | 手数が交点数の 4 倍に達したら、その時点の面積得点で勝敗を決める |
| seed | 探索は 1。世代・盤・対局番号から各対局の seed を決める |

候補は各重みの平均と標準偏差から抽出し、探索範囲に収めます。初期標準偏差は探索幅の 1/8、以後は旧標準偏差の 0.6 倍と上位候補の標準偏差の 0.4 倍を足し、探索幅の 1/100 を下限にします。同じ世代の候補比較には共通の対局 seed を使います。

この設定では 1 世代あたり候補の評価が 24,576 局、平均候補の確認が 1,536 局、60 世代で計 1,566,720 局です。

探索の生ログを [search-progress.txt](experiments/2026-10-20/search-progress.txt)、標準出力を [search-result.txt](experiments/2026-10-20/search-result.txt) に保存しています。これらは当時の `tune-full.log` と `tune-full.out` の内容です。

## 探索結果から採用値を決めるまで

探索が最後に返した champion を **A**、第 59 世代の上位候補の平均を **B** と呼びます。A が最後に昇格したのは第 11 世代で、その後は平均候補の勝率が昇格条件を超えませんでした。第 59 世代のログでは、平均候補の対 champion 勝率は 51.0% です。

そのあと A と B を小数第 3 位までの値で直接対戦させ、評価要素を 1 つずつ無効にする比較も行っています。以下はすべて `--games 2000 --seed 99`、各盤 2,000 局、全 6 盤で 12,000 局の結果です。「勝数・勝率」は表の左側の AI の成績です。

| 比較 | 勝数 / 局数 | 勝率 | 出力された 95% 区間の半幅 |
| --- | ---: | ---: | ---: |
| A 対 B | 5,934 / 12,000 | 49.5% | ±0.9 ポイント |
| B 対 legacy | 11,618 / 12,000 | 96.8% | ±0.3 ポイント |
| A 対 legacy | 11,612 / 12,000 | 96.8% | ±0.3 ポイント |
| B 対 B の `territory` を 0 にしたもの | 7,238 / 12,000 | 60.3% | ±0.9 ポイント |
| B 対 B の `atari` を 0 にしたもの | 5,978 / 12,000 | 49.8% | ±0.9 ポイント |

勢力評価を残した B は、勢力評価だけを外した B に 60.3% 勝ちました。これは両者の直接対戦の勝率であり、対 legacy 勝率が 10.3 ポイント上がったという測定ではありません。アタリ評価の有無では改善が確認できず、実装から外しました。

最終的には、B からアタリ評価を取り除き、残る重みを小数第 2 位に丸めて採用しています。A より B を採用する理由はログには明記されていません。直接対戦はほぼ互角で、B の明確な優位を示す結果ではありません。

Claude の最後の報告には「12 個の重みを 60 世代で探索」とありますが、実行ログと試作時のソースでは探索対象は 13 個です。アタリ評価の削除後、現行実装の探索対象が 12 個になっています。

## 最終版の検証

アタリ評価を削除し、丸めた値を `Params::tuned()` に設定したあと、次の対局を行いました。

```sh
cargo run --release -- match tuned legacy --games 2000 --seed 2026
```

| 盤 | 最終版の対 legacy 勝率 |
| --- | ---: |
| 球面 n=3（小・56 点） | 90.5% |
| 球面 n=4（標準・98 点） | 98.2% |
| 球面 n=5（大・152 点） | 99.5% |
| トーラス 7×7 | 94.7% |
| トーラス 9×9 | 97.0% |
| トーラス 11×11 | 99.8% |
| 合計（11,593 / 12,000 勝） | 96.6% |

合計の出力は `95% CI ±0.3` でした。盤ごとの数字は小数第 1 位に丸めた出力で、盤別の勝数はセッションには出力されていません。

丸めた最終版と、アタリ評価を外した B（小数第 3 位の値）の比較も `--games 2000 --seed 2027` で行い、最終版が 5,963 / 12,000 勝、49.7%（±0.9 ポイント）でした。この比較では丸めによる明確な悪化は確認できませんでした。

これらの区間はツールが `1.96 * sqrt(p * (1 - p) / n)` で出す正規近似です。固定した相手・盤・seed に対する成績であり、人間相手の棋力や、一般的な囲碁 AI に対する強さを測ったものではありません。

### JS への反映と一致確認

採用値を [src/ai.rs](src/ai.rs) の `Params::tuned()` と [dist/engine.js](../../dist/engine.js) の `AI_WEIGHTS` の両方に反映しました。試作したアタリ数の計算とその重みは、Rust / JS の双方から削除しています。

```sh
# tools/ai-tuner/ で実行
cargo run --release -- selftest
cargo run --release -- parity parity.json --count 300

# リポジトリ直下で実行
node tests.mjs
```

最終版の 300 局面で、合法手順の再生・重みの一致・乱数加点を 0 にした選択手の一致を確認しました。この fixture は [parity.json](parity.json) として保存され、[tests.mjs](../../tests.mjs) が検証します。調整前の 600 局面の確認とは別の検証です。

セッションではエンジン、コミ、棋譜、保存復元、投影、描画、姿勢・回転、UI の各テストを実行し、成功出力を確認しています。UI シミュレーションは 360×640、390×844、844×390 の 3 サイズでした。これらは実ブラウザやスマートフォンでの表示確認を代替するものではありません。

### 当時の速度測定

Rust の `bench` は legacy 同士を各盤 40 局、直列に対戦させた測定です。球面 n=3・4・5 がそれぞれ 0.6 / 1.6 / 3.2 ms/局、トーラス 7・9・11 が 0.5 / 1.2 / 2.6 ms/局でした。最終版の速度や探索全体の並列処理時間とは区別します。

最終版の JS `chooseMove` は Node.js 上で対局中に計測しています。

| 盤 | 計測した手数 | 中央値 | 最大値 |
| --- | ---: | ---: | ---: |
| 球面 n=5 | 145 | 0.68 ms | 4.36 ms |
| トーラス 11×11 | 116 | 0.32 ms | 2.38 ms |
| 球面 n=3 | 49 | 0.12 ms | 0.58 ms |

ウォームアップや乱数 seed を固定した厳密なベンチマークではなく、当該環境での単発測定です。ブラウザや別端末での所要時間を保証する数値ではありません。

## 再実行時の注意

現行のソースでは試作時の `atari` が削除され、探索次元が 13 から 12 に変わっています。そのため、同じ seed とオプションで `tune` を実行しても、この記録の探索は再現しません。当時の試作ソース一式は今回保存するログには含まれていません。

最終版の対 legacy 成績は上記の `match` コマンドで再確認できます。丸め前の B との比較は次のコマンドです（`tools/ai-tuner/` で実行）。

```sh
cargo run --release -- match tuned '{savePerStone:2.099,saveCap:6.661,killPerStone:2.326,killCap:4.69,liberty:3.142,enemyAdjacent:0.661,friendAdjacent:-0.852,selfAtari:-20.158,crowded:-3.143,open:-2.127,passBelow:-0.513,territory:0.27}' --games 2000 --seed 2027
```

今後もう一度探索する場合は、使用したソースのコミット、探索ログ、採用した候補、検証用 seed と勝数を一緒に残すと比較できます。今回の勝率は入門向けの旧 AI との差を示すもので、深い読みや死活判断の改善を確認したものではありません。
