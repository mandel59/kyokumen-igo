# Kyokugo AI v3（実験実装）

v3 は小型 GNN と、根の逐次半減・内部のバッチ PUCT を組み合わせた MCTS です。モデルは **64 チャネル × 6 残差ブロック、120,905 パラメータ**。配信モデルの ONNX は 502,401 bytes です。

通常対局の標準はv2です。実験用v3には、[KataGoの平面盤方策を蒸留したモデル](../../../experiments/ai/v3/2026-10-27-katago-distillation/README.md)を採用しました。同じ120,905パラメータ・64訪問で、独立評価の更新前v3への得点率は平面86.5%、曲面62.0%、方策対照に対しては平面67.7%でした。全9盤の事前採用基準とPCのCPU/WASM・WebGPU速度基準を通過しています。スマートフォンの実機速度は未計測です。

## 試す

球面・トーラスに加え、平面の7・9・11路盤でもv3を使えます。平面盤の隣接関係を探索へ渡し、端はつなぎません。配信モデルはKataGoの平面盤教師と曲面の既存教師データを混ぜて再学習したものです。

[開発手順](../../../tools/ai-gnn/README.md) に従って推論ランタイムを用意し、通常の HTTP サーバーで `dist/` を配信します。

- `/?ai=v3`：WebGPU を優先し、利用できなければ同じモデルを WASM で推論。スマートフォンでは WebGPU を使わず WASM で推論。
- `/?ai=v3&backend=wasm`：CPU / WASM 推論を指定。
- `/?ai=v3&backend=webgpu`：スマートフォンでも WebGPU を優先。
- アプリ情報の「AI」タブで v2 / v3 を切り替えられ、選択はこの端末に保存されます。`?ai=v2` / `?ai=v3` は保存された選択より優先されます。
- Web Worker と SIMD 対応の WebAssembly が無い端末では v3 は選べず（`?ai=v3` や保存済みの選択も無視して v2 を使います）、AI タブの v3 は選択不可になります。v3 には JS 版がありません。
- オプションなし：従来の v2。v3 のモデル・推論ランタイムは取得しません。

v3指定時は初期化・GPUカーネルのウォームアップ完了を待ち、最初の手番からv3を使います。モデル・ランタイムの取得や実行に失敗した場合はv2へ戻ります。v2はWASM、利用不能時は同じRustから生成したJSで動作します。

## 入力 ABI v1

160 交点にパディングし、実際の点をマスクします。交点 ID や描画座標を学習しません。隣接行列は `A[p,q] = 1 / degree(p)`（隣接時）、それ以外は 0。次数3と次数4をそれぞれフラグで表し、平面盤の隅の次数2は両方0とします。

| チャネル | 内容 |
| --- | --- |
| 0–2 | 自石・敵石・空点 |
| 3–10 | 自分 / 相手の連の呼吸点：1・2・3・4 以上 |
| 11–12 | 自分 / 相手の連の大きさ：`log1p(size) / log1p(points)` |
| 13–14 | 次数 3 / 4 |
| 15–18 | 直前から 4 手の着手点。パスは全 0 |
| 19–26 | 直前から 4 局面の自石 / 敵石。現在の手番基準 |
| 27 | 合法手。位置的スーパーコウを含む |
| 28 | 着手で取れる石数：`sqrt(captured / points)` |
| 29 | 着手後の呼吸点：`min(liberties, 8) / 8` |
| 30–31 | 隣接する自石 / 敵石の数 ÷ 4 |

全体特徴は、自分側へのコミの寄与 ÷ 点数、点数 ÷ 160、球面 / トーラス、連続パス数 ÷ 2、手数の進行度、黒番フラグ、定数 1 の 8 要素です。

盤種の2要素は球面が `[1,0]`、トーラスが `[0,1]`、平面が `[0,0]` です。特徴ABI 1の32チャネル・全体8要素とモデルの形状を維持し、球面・トーラスの特徴値は変更しません。平面盤の2つのフラグの組み合わせを追加するために、既存の重みを変換する必要はありません。

過去 4 局面は完全なスーパーコウ履歴ではありません。探索では元の対局履歴と各経路の履歴を使って合法手を計算します。盤面だけでノードを統合せず、異なる履歴の評価結果も共用しません。

## モデル

入力を 64 チャネルへ写像し、次の残差ブロックを 6 回適用します。

```text
g = concat(masked_mean(H), global_features)
Z = ReLU(local(H) + near(A @ H) + broadcast(context(g)))
H = mask * (H + 0.25 * out(Z))
```

パディングは各ブロックで消去し、全体平均からも除きます。出力は Policy 161 logits（160 がパス）、勝ち / 引き分け / 負けの 3 logits、点数で正規化した得点差、各交点の自分 / 中立 / 相手の 3 logits です。

MCTS の値は `P(win) - P(loss)`。手番をまたぐごとに符号を反転します。Score・Ownership は補助学習に使い、探索値へ加算しません。終局では NN を使わず、実際の面積採点で勝敗を確定します。死石の自動除去はしません。

## 探索・実行

- 相手が直前にパスし、自分もパスすれば現在の面積採点（コミ込み）で勝つ場合は、根の候補をパスだけにして勝ちを確定させます。NN の評価や訪問数に左右されず、任意の敗北確定フィルターを無効にした場合も適用します。引き分けはこの優先処理の対象外です。それ以外の根では後述する無駄な打ち込みと、生存証明済みの自石だけで囲まれた一点の眼への着手を除外します。終盤フィルターは、相手のパス後、全石がBensonの無条件生存石で、全空点がその生存石の確定した眼領域に含まれる場合、引き分けや負けでもパスで終局します。未確定の石・中立点・証明できない広い空間があれば、この打ち切りを適用しません。NNの低い勝率だけでは打ち切りません。残りの合法手とパスを探索します。Policy を PUCT の事前確率に使用し、残した手の一様分布を 2% 混合します。
- 1–8 葉をまとめ、未完了経路を予約して同じ葉への要求集中を抑えます。根の最初の評価は 1 葉です。
- 最大 8 局面を評価します。専用 WebGPU と CPU は実際の局面数だけを計算します。ONNX WebGPU へフォールバックした場合は 8 局面固定で、空き枠をダミーで埋めます。
- ブラウザーの探索予算は1手64訪問です。Pixel 8aで全6盤を実測し、最も遅い盤のP95がChrome / WebGPUで269.8ms、Firefox / WASMで245msだった設定をPC・スマートフォン共通で使います。目標300msには400msまでの余裕を含め、追加の20%は差し引きません。[計測記録](../../../experiments/ai/v3/2026-10-22-pixel8a-visits/README.md)を参照してください。端末速度で打ち切らず、終局の確定評価も訪問に数え、バッチ末尾も残り訪問数に制限します。敗北確定時は最初の評価後にパスします。待ち時間は端末性能で変わります。
- 開発用APIの `chooseMove(position,{maxSimulations})` で訪問数を指定できます。`budgetMs` を明示した場合だけ時間による途中終了も有効です。既存の時間比較・ベンチマークはこの明示指定を使います。
- 2026-10-22のPUCT構成による共通64訪問の実ブラウザー対戦では、当時のv2 WASM・深さ4に76勝20敗、勝率79.2%でした。全6盤・先後交換96局、ペアを単位にした95%区間は70.8〜86.5%です。以前の300ms構成の対v2勝率94.8%とは条件が異なり、64訪問版と直接対戦させた結果ではありません。[64訪問の棋力評価](../../../experiments/ai/v3/2026-10-22-fixed64-strength/README.md)に条件・全棋譜・検証を記録しています。
- 木は最大 8,192 ノード、1 経路 256 手。初版では手番ごとに作り直し、各バッチで根の履歴を再生します。
- 評価は一度に 1 バッチ。要求 ID・世代・出力長・有限性を検証します。キャンセル後の評価は反映しません。

未探索手の初期評価はモデルの `manifest.search.fpu` で指定します。`0` は評価 0、`1` は親の実訪問の平均値、`2` は親の平均値から `0.2 × sqrt(訪問済みの事前確率質量)` を引いた値です。指定がないモデルは方式 0 を使います。予約中の仮想損失は親の平均値に含めず、自己対局のノイズ付き根では方式 2 の減点を 0 にします。開発用の `start(position,{fpu})` と `createV3AI({fpu})` でモデルの設定を上書きできます。

ビルド時に探索 WASM の SHA-256 を取得 URL のキーへ反映し、探索設定を追加した新しいバイナリを取得できるようにします。

WebGPU は専用 WGSL を優先します。1 点につき最大 4 個の隣接点だけを集計し、各残差ブロックの local / near / ReLU / out / 残差加算を一つのカーネルで計算します。全体集計と文脈の計算を合わせてブロックごと 2 dispatch、全体で 15 dispatch です。重み・中間結果・入出力・読み戻し用バッファを保持し、通常は Policy・Value を一度の map で CPU へ読み戻します。盤ごとの隣接行列も対局間で再利用します。

モデルは同じ FP32 のままです。`weights.f32` は PyTorch の重みを入力チャネル優先に転置した 483,620 bytes の補助ファイルで、量子化は行いません。manifest の `webgpu` が形式 1・ONNX の SHA-256・重みの SHA-256 を結びつけます。対応情報がない古いモデルや専用 GPU の失敗時は、同じモデルの ONNX WebGPU、`auto` ならさらに WASM へ戻ります。CPU 指定時は CPU 専用の ONNX Runtime を使います。`auto` は GPU 優先で、速度による自動選択は行いません。

2026-10-22 の Edge / NVIDIA Blackwell / Ryzen 3700X の比較では、GPU の 8 局面評価が中央値 10.9→3.45ms、CPU の 1 局面評価が 13.9→2.1ms、300ms の GPU 探索が 201→573 simulations になりました。全 6 盤・実バッチ 1 / 8 の比較で最大出力差は約 0.0000062 です。[条件・生データ・再現手順](../../../experiments/ai/v3/2026-10-22-inference/README.md) を参照してください。

### 有限予算の根の比較

標準の64訪問では、根の事前確率が高い最大8手を選び、評価を集めて候補を半分ずつに絞ります。各段階の予算を8評価のバッチに揃え、最後の端数を残った候補へ配分します。内部ノードは従来のPUCTを使い、評価待ち・そのバッチで探索先が尽きた枝を重複して選ばず、可能な限りバッチを埋めます。

根の比較値は `log(prior) + 0.4 × (50 + 最大訪問数) × Q`。最終手は残った候補の比較値で選び、有限予算時の `policy` はその正規化分布です。生の訪問数は `diagnostics.rawVisits` で取得できます。確定した勝ち・負けはこの比較より優先します。Gumbel乱数は使わず、内部の選択をPUCTに保った独立実装です。[参考論文](https://openreview.net/forum?id=bERaNdoegnO)の手法を基にしています。

低レベルAPIでは最初の `collect(batch,remainingVisits)` で全体予算を宣言するとこの方式を使います。残り数なしの `collect(batch)` は従来PUCTです。途中で宣言した全体予算を増減した場合はPUCTへ戻り、追加探索やキャンセル後の再開を継続できます。モデル・特徴ABI 1・探索ABI 3・標準64訪問は維持しています。

### 探索内の確定勝敗

探索中も、2回目のパスで勝てる局面はニューラルネットを呼ばず、手番側の確定勝ちとして扱います。終局した局面は実際の面積得点から勝ち・引き分け・負けを保存します。子に確定負けが1つあれば親は勝ち、全ての合法手が確定した場合だけ親の引き分け・負けを確定します。未評価の手や評価待ちの手を、負けとみなすことはありません。

確定負けの手より未解決の手を優先して探索し、最終方策からも確定負けの手を除きます。全ての手が負ける場合は合法な方策を残し、確定勝ちがあれば訪問数より優先します。ニューラルネットの勝率や得点予測だけから確定判定を作ることはありません。正確な値の逆伝播も1訪問として数え、通常の64訪問制限を維持します。詳細と探索係数の不採用候補は[実験記録](../../../experiments/ai/v3/2026-10-25-search-proof/README.md)に保存しています。

### 無駄な打ち込みの回避

2026-10-22 から、学習重みとは独立した根の戦術チェックを使います。[修正・検証記録](../../../experiments/ai/v3/2026-10-22-tactics/README.md) を参照してください。

1. グラフ上の連と空領域に Benson の固定点を適用します。二つ以上の vital region を維持する相手の連を残し、その生きた連の呼吸点だけから成る空領域への打ち込みを避けます。単に相手に囲まれた大きな領域全体を死と判定するものではありません。
2. 呼吸点が 1–2 の孤立した新石について、着手後 3 手以内に相手が確実に取れるか読みます。相手の攻めは呼吸点への着手、受けはパスを含む全合法手を確認します。深さやノード数の上限で未確定になった手は除外しません。

短手数の読みでは、石を取る手、味方への連絡・救出、相手の弱い連への働きかけは残します。取られた後に 8 子を取り返すウッテガエシの回帰局面も確認しています。上限は根全体 1,024 ノード、候補ごと 384 ノードです。チェックは手番ごとの根で一度だけ行います。

これは探索上の除外であり、ルールの合法手・NN 入力の合法手特徴・採点は変更しません。特徴 ABI は 1 のまま、探索 WASM ABI は 3。複雑な攻め合い・長いシチョウ・既にある死に石の全判定は未対応です。

### 敗北が確定した後のパス

相手の Benson 生存石数を `E`、全交点数を `N` とすると、相手が生きを維持する限り自分が取れる交点は最大でも `N−E` です。自分が黒なら `2E + コミ > N`、白なら `2E − コミ > N` のとき、残りを全て自分の得点にしても勝てません。この十分条件を満たす根ではパスだけを残し、最初の評価バッチで探索を止めます。現在の面積差や NN の推定勝率での打ち切りは行いません。引き分けの可能性が残る等号も対象外です。

判定は毎手作り直し、相手が生きを崩して条件が成立しなくなれば通常探索に戻ります。投了操作や自動終局は追加せず、対局は通常どおり連続二回のパスで終わります。確定条件を満たさない負け局面の粘りは残り得ます。

報告された球面 5・白 AI の棋譜では、166 手目で黒の生存石が 80、白の最大得点が `152−80+6.5=78.5` になりました。166–230 手目の白番 33 局面すべてでパスを選び、元の棋譜にある 31 回の継続着手を抑制しています。[棋譜の再現・ブラウザ検証](../../../experiments/ai/v3/2026-10-22-endgame/README.md) を参照してください。

専用 GPU の通常経路では ONNX Runtime を読み込みません。フォールバック用の ONNX Runtime Web 1.30.0 は別の依存です。WASM を gzip 圧縮して配信し、ブラウザで展開します。CPU 専用は約 3.7 MB（展開後約 14.2 MB）、ONNX WebGPU は約 6.6 MB（約 26.8 MB）で、必要な側だけ取得します。初期化・メモリの負担はモデルの約 0.5 MB より大きくなります。

## 現在の配信モデル

平面96局と曲面の既存48局を使い、KataGoのroot edgeVisitsから着手方策を蒸留しました。勝敗・得点・所属はアプリのルールによる実際の終局値です。候補と追加学習対照を同じ条件で学習し、独立384局と全9盤の固定局面速度比較を通過しました。[全記録](../../../experiments/ai/v3/2026-10-27-katago-distillation/README.md)と[採用profile](../../../experiments/ai/v3/2026-10-27-katago-distillation/data/student-profile.json)を参照してください。ONNX SHA-256は `d866f7d8ec0c3a5813832da25f925c6fb74662eee9b2511eedbe379bd09e1f7f`。

## 2026-10-25時点の配信モデル

4,096訪問のオフライン教師で同じ自己対局局面を再解析し、従来と同じ120,905パラメータの生徒へ蒸留しました。学習36局・検証12局を対局単位で分離し、共通教師の検証損失でepoch 8を選択しています。開発対戦96局と別の開始条件で独立192局を評価し、全6盤で更新前モデルを上回りました。ブラウザーでは生徒だけを64訪問で動かします。

## 過去の比較対象

2026-10-22 の [学習改善](../../../experiments/ai/v3/2026-10-22-learning/README.md) では、96 局の探索自己対局と敗北確定後の取り進めから教材を追加しました。再開前の対局分割の固定、派生局面を含む対局単位の分割、データ源・盤・対局・進行度の均等化、CUDA 上のテンソル再利用、cosine 学習率、EMA、更新前も含む検証最良の選択を実装しています。低確信度の着手教師の抑制と旧 prior への KL 制約も比較します。採用判断は検証損失と別の開始局面で対戦して行い、失敗候補も保存します。

[改修・学習計画](../../../experiments/ai/v3/2026-10-22-learning-revision/plan.json)に従い、通常局面の共通教師を使う選抜へ切り替えました。敗北確定局面は学習・選抜から除き、既存ルールで選べない旧教師の着手も着手損失から除外しています。同一局面の元の128訪問、ノイズなし128訪問、ノイズなし512訪問を比較し、着手の対象局面を抽出した後もデータ源ごとの損失比率を保ちます。第2世代では新旧の自己対局も均等化しました。固定訪問数の棋力評価と、実際のWorker・WebGPUでの同時間評価を分けて保存しています。

この時点の採用モデルは第1世代の元の128訪問教師・epoch 8でした。同じ探索を使った旧重みとの独立384局では231勝153敗（60.2%、先後交換ペアによる95%信頼区間55.5〜64.8%）、全6盤で採用基準を通過しました。新モデルと親の実訪問平均を使う探索を組み合わせた実Worker・WebGPUの300ms対戦は、従来構成に32勝16敗でした。この48局は実行環境の統合確認です。ウォーム推論P95は両者4.1msでした。全条件の通過後に実験用v3へ反映しています。第2世代は検証損失が改善しても第1世代との対戦が48勝48敗だったため採用していません。[機械可読の結果](../../../experiments/ai/v3/2026-10-22-learning-revision/data/summary.json)と[成果物のハッシュ目録](../../../experiments/ai/v3/2026-10-22-learning-revision/manifest.json)に、選択条件・全候補・不採用理由・棋譜・実行コマンド・ソース差分を記録しています。

同じ実時間での対 v2 評価、さらに多くの自己対局、モバイル端末の検証が必要です。連ノード、本格的な局所戦術探索、FP16、Graph Capture、着手・巻き戻しによる高速化は未実装です。
