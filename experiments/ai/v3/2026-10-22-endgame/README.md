# Kyokugo AI v3：実棋譜の終盤の粘り

報告された棋譜では、白 AI が 166 手目でパスした後、168–228 手目に 31 回着手し直していました。相手の生き石だけで逆転不能を確認する判断を追加し、166 手目以降の白番 33 局面すべてでパスすることを検証しました。モデルの再学習はしていません。

## 原因と変更

前の根の戦術チェックは孤立した新石が対象で、既存の死に石への継ぎ足しは残していました。また、負けが確定した後も探索の勝敗推定と Policy に従い、パスから着手へ戻ることがありました。

Benson の空領域による固定点から相手の生存石だけを数え、その石が残る限り他の全交点を自分の得点にしても勝てないとき、根の候補をパスに限定します。引き分けが残る場合は継続します。黒番・白番・コミを区別し、毎手再計算します。相手が生きを壊した場合は探索を再開できます。終局ルール・採点・合法手・NN の特徴と重みは維持しています。

今回の球面 5 は 152 交点、コミ 6.5。166 手目の黒の生存石は 80 個で、白の最大は `152−80+6.5=78.5` 点。黒が生きを維持すれば少なくとも 1.5 点差で白が負けます。164 手目はこの条件を満たさず、通常探索を続けます。

## 検証

- `v3-tests.mjs`：実棋譜の白番 33 局面で、任意の着手を強く推す偽 NN 評価でも全てパス。元の継続着手 31 回を抑制。ゲームの状態を変更しないことも確認。
- Rust 5 テスト：既存の戦術チェック・PUCT に加え、全 6 盤・両色で敗北条件、コミ、引き分け境界を確認。生き石が少ない盤や一眼の未確定な相手だけでは打ち切らないことを確認。
- 実モデルの同一 seed 比較：[replay.json](data/replay.json)。根の戦術チェックは両方有効にし、敗北確定後のパスだけを切り替え。指定 64 simulations、seed 3、CPU 推論。追加判断が働いた側は最初の 1 評価で停止。
- 実際の Edge Worker：[browser-verification.json](data/browser-verification.json)。WebGPU / WASM 両方で下記の代表局面の判定が一致。166 手目以降は 1 バッチで応答。6 盤の探索、NN 数値照合、キャンセル、実際の Worker の v3 選択も成功。
- 既存の棋譜・v2 WASM / Worker・UI テストも成功。

着手番号は内部の 0 始まり交点 ID です。比較は同じ棋譜の途中局面から独立に行い、修正後の一局全体を指し直したものではありません。対局数による棋力評価ではないため、勝率や区間推定は算出しません。これは敗北の十分条件であり、条件を満たさない負け局面の粘りや一般の死活判定は未解決です。

## 再現

```sh
node tools/ai-gnn/build.mjs
node v3-tests.mjs
node tools/ai-gnn/replay-endgame.mjs --output tools/ai-gnn/target/endgame-replay.json
node tools/ai-gnn/test-browser.mjs --output tools/ai-gnn/target/endgame-browser.json
```

元棋譜は [reported-record.json](data/reported-record.json)、実行時点の差分は [source.patch](data/source.patch)、識別情報・SHA-256 は [manifest.json](manifest.json) に保存しています。前の検証は [戦術チェック](../2026-10-22-tactics/README.md)、仕様は [v3](../../../../docs/ai/architectures/v3.md) を参照してください。
