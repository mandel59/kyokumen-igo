# v3の探索内の確定勝敗と探索係数の比較

探索途中でパスにより即勝ちできる局面を正確に評価し、終局の勝敗を探索木へ伝える修正を採用しました。相手が勝ちを確定できる手を最終方策から除き、未解決の手に訪問を使います。学習モデル、特徴ABI 1、探索ABI 3、標準の64訪問、探索係数1.5は維持しています。

最終版は旧v3に48勝48敗でした。先後交換ペア単位の層別bootstrapによる95%区間は50.0%〜50.0%です。総合的な棋力上昇の事前基準には届いていないため、棋力全体の向上とは結論しません。採用理由は、敵対的なNN出力でも確定勝敗を正しく扱えることです。

全48組の先後交換ペアがそれぞれ0.5点だったため、上のbootstrap区間は50%に退化しています。一般の局面でも棋力が等しいことや、将来の成績の不確実性がゼロであることを意味しません。

## 計画と選抜

[当初計画](plan.json)では、全6盤、コミ6.5、4手のランダム開始配置、先後交換、64訪問で比較しました。開発seedは2026102501で各候補24局。探索係数0.75・1.5・2.25を同じ開始配置で比較し、最高得点、同点なら1.5を優先する基準を先に記録しました。独立評価はseed 2026102511の96局、53/96点以上・各盤6/16点以上・打ち切りなしを採用基準としました。

正確な葉評価だけの候補は11勝13敗。勝敗伝播を加えた係数1.5は13勝11敗、0.75は15勝9敗、2.25は13勝11敗でした。開発で選んだ0.75を固定した独立96局は49勝47敗（95%区間41.7%〜59.4%）で基準未達となり、探索係数変更を不採用としました。

その96局の終了後、元の係数1.5に戻して確定勝敗の修正だけを残す[最終計画](data/final-plan.json)を記録しました。追加の係数探索は行わず、新しいseed 2026102521で96局を最後まで実行しました。当初計画にも、棋力基準未達時は正確な終局判定の修正だけを残して総合棋力向上を主張しない方針を含めています。

## 実装と検証

終局と勝てる2回目のパスだけから確定値を作ります。子に負けがあれば親の勝ち、全ての手が確定して初めて引き分け・負けを伝播します。NN評価、未訪問手、評価待ちの予約は証明に使いません。確定負けの枝は未解決の枝より後回しにし、確定勝ちは訪問数に優先します。全敗時も合法な方策を維持します。

全6盤・両色・半目勝敗と引き分け境界で、旧バイナリーは新しい回帰テストに失敗し、修正版は通過します。敵対的な方策・勝敗予測でも、相手に即勝ちのパスを渡す手を選ばないことを64訪問で確認しました。多段の勝敗反転、未解決の返し、全敗、訪問数、キャンセル、既存の戦術・捨て石・スーパーコウ・終盤・Worker・UIを検証しています。[テスト記録](data/final-verification.json)と[実ブラウザー検証](data/browser-verification.json)を保存しています。

## 計算時間と限界

環境は 156.0.4314.42 / AMD Ryzen 7 3700X 8-Core Processor             。同じWorkerで専用WGSL WebGPUを使い、両者を逐次実行しました。最終版の1手平均は32.26ms、P95は39.50ms（4591手）。旧版は平均32.40ms、P95は39.30ms（4587手）でした。計測範囲は実際のchooseMove呼び出しで、履歴復元・探索・推論・待機を含み、初期化・描画を含みません。両者で到達する局面は異なり、同一局面の純粋な速度比較ではありません。各実行の着手時間合計とウォームアップ推論は[実行記録](data/execution.json)に保存しています。壁時計での総所要時間は計測していません。

固定64訪問での結果であり、同一計算時間、スマートフォン実機、別の探索量、対v2の改善を示すものではありません。モデルの再学習は行っていません。探索係数の開発成績が独立評価で再現しなかった結果も含めて保存しています。
