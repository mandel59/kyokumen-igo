# KataGoの平面盤方策からv3への蒸留

## 結論

採用基準を通過した候補を実験用v3へ反映しました。 平面3盤での基準v3に対する得点率は86.5%（83勝0分13敗、ペア95%区間78.1%–93.8%）。同じ追加学習を行う方策対照への得点率は67.7%（95%区間58.3%–77.1%）、曲面6盤では62.0%（95%区間55.7%–68.2%）でした。[判定](data/decision.json)と[独立評価集計](data/independent-summary.json)を保存しています。

## 識別情報

- 実験ID：v3/2026-10-27-katago-distillation
- 生徒：現行と同じ64チャネル・6ブロック・120,905パラメータ。探索は全て64訪問、FPU 1。
- 教師：KataGo v1.18.1 OpenCL、公式通常ネット kata1-b10c128-s1141046784-d204142634、512訪問。最強・最新ネットではなく、生成速度と予備対戦で選んだ小型教師です。
- 学習：PyTorch CUDA、RTX 5060 Ti。対戦：ONNX Runtime CPUと現行WASMの研究用プレイヤー。
- 基準commit：67e9bffcb292e594001726c1eb7f0009ec39b34a。追加ツールと速度計測の変更は[data/source.patch](data/source.patch)、ソースは[data/source/](data/source/)に保存。実行上の設定訂正・元のdriverとの差は[data/execution-notes.json](data/execution-notes.json)に記録。

## 実行前の計画

[plan.json](plan.json)で、データ収集・学習・独立評価の前に条件を固定しました。教師は学習に使わない先後交換12局で基準v3に12勝し、予備基準を通過しました。[速度試験](data/benchmark.json)から512訪問を選びました。

平面7/9/11路それぞれ32局を生成し、各盤24局を学習・8局を検証へ分けます。各盤16局はKataGo自己対局、16局は基準v3自己対局です。曲面6盤は過去の教師蒸留48局を再生し、配信モデルの対局分割を維持します。全9盤を均等化して16エポック学習し、epoch 0/4/8/12/16から共通教師による通常局面の検証損失で選択します。開発対戦後も候補・ハイパーパラメータ・独立局数を変更しません。

独立評価は候補対基準v3が全9盤・各16先後交換ペアの288局、候補対方策対照が平面3盤・各16ペアの96局、合計384局です。初期4手と同じ手数の乱数列を先後で共有します。集計は盤別に層化したペアbootstrapです。

## 方法と結果

面積採点・位置的スーパーコウ・自殺手禁止・死石自動除去なし・コミ6.5で、全着手と最終ラベルはアプリのGameで判定します。教師のroot edgeVisitsを合法手上で正規化し、2%の合法手一様分布を混ぜます。勝敗・点数・所属は予測値ではなく実際の終局結果です。

比較用2モデルは入力局面、終局ラベル、分割、検証目標、サンプリング、初期重み、更新回数を共通にし、学習時の方策目標だけをKataGoと基準v3で変えます。対照もKataGo自己対局由来の局面と終局結果を共有するため、「KataGoを全く使わない」対照ではありません。検証目標も共通KataGo方策です。

証明済み敗北局面を除いた実際の学習数は9263局面、検証数は3123局面です。

生成した平面96局・7734局面と曲面4719局面を使用しました。[全根の再生監査](data/data-audit.json)と[学習テンソルの一致監査](data/paired-tensor-audit.json)があります。蒸留候補はepoch 16、方策対照はepoch 16を選択しました。

## 採用と限界

採用基準を通過した候補を実験用v3へ反映しました。 32局/盤の初期試験で、教師は小型の古い通常ネットです。曲面への転移改善やKataGo相当の棋力を主張する試験ではありません。教師のスレッド割当とGPU演算のため、seedだけで全出力のビット一致を保証しません。全ての使用方策は保存した探索統計から再構成できます。

公式ネットの出所・SHA-256は[data/provenance.json](data/provenance.json)、ネットの許諾文は[data/KataGo-NN-LICENSE.txt](data/KataGo-NN-LICENSE.txt)です。生徒パッケージにも出典と許諾文を添えています。これは出典を明示する運用方針で、ライセンス本文に蒸留専用条項があるという意味ではありません。

## 再現手順と保存データ

実行ツールはtools/ai-gnn/katago-distill-*.mjsです。新しい作業ディレクトリにKataGoを用意し、保存したplan.json・設定・分割を使用します。各工程の正確なコマンドと経過時間はdata内の*-command.json、ログは*-log.txtです。実行済みのtargetやこのdataを上書きしません。

生徒のONNX・FP32 GPU重み・PyTorchチェックポイントは[data/teacher-model/](data/teacher-model/)、方策対照は[data/control-model/](data/control-model/)、更新前は[data/baseline/](data/baseline/)です。教師ネットと実行バイナリ自体は同梱せず、公式取得URLとハッシュを保存しています。
