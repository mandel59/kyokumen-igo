# 戦術を優先する根の8候補

1枠案・2枠案とも開発48局は24勝24敗で、採用しません。1枠案は24組すべて、2枠案は24組で先後交換時の棋譜が一致しました。候補を追加しても今回の試行では着手・勝敗の改善に結び付きませんでした。配信WASM・モデルは維持し、Rustの変更も戻しました。

[事前計画](plan.json)は、取りの石数とアタリからの延長で救う石数を得点にし、着手後2呼吸点以上の合法・未除外手から最高1/2候補を保護するものです。NN上位候補を置換して総数8を保ち、元の事前確率・比較式・内部PUCT・64訪問を変更しません。既に上位8にある戦術も保護枠を使い、弱い戦術を際限なく追加しません。

基準は174605da46f66200cdd2d2a173aa633b0b5941cd、モデル8e5b41e3974c、探索862f1120b03aです。開発seed2026102611、各盤4組、コミ6.5、初期合法4手と先後交換、同じモデル・FPU1・64訪問です。27/48以上を満たさず、独立192局・速度測定へ進みませんでした。

全6盤の低事前確率の取り・救出、合法マスク、自アタリ除外、既存の勝敗確定・予約解放・奇数予算を含むネイティブ14件とWASM回帰が両案で通過しました。以前の学習用自己対局を使う診断では、ノイズなし・候補9手以上の6,291局面のうち1枠で1,095局面にNN上位8より低い戦術候補がありました。診断は今回の対戦から独立し、閾値の選び直しには使いません。

最初の評価ランナーには、後段の速度・独立評価が配信WASMを参照するパスの誤りがありました。開発途中で自分のプロセスツリーを停止し、不完全な記録をabortedとして残し、同じ事前設定で再実行しました。完了した両対戦のWASMハッシュを検証済みです。

[manifest](manifest.json)に全データのハッシュ、候補ソース・WASM・コンパイル／テストコマンド・全棋譜を保存しました。source.patchは基準コミットから1枠案への差分です。2枠はslots2-mcts.rsを使います。診断入力は前のonpolicy-distillationアーカイブのselfplay.jsonl.gzを展開したものです。
