# 無駄な打ち込みの回避（2026-10-22）

NN の楽観的な評価により、明らかに取られる場所へ孤立した石を打つ問題に対し、根の候補生成へ戦術チェックを追加しました。モデル重み・特徴 ABI・ゲームの合法手と採点は変更していません。

## 判定

- 相手の連と空領域について Benson の固定点を計算。無条件に生きた連の vital region（全点がその連の呼吸点となる空領域）への打ち込みを根から除外します。空領域だけを扱う保守的な判定で、既存の敵石を含む領域や、単に相手に囲まれただけの広い空間を同じ扱いにはしません。
- 孤立した新石の呼吸点が 1–2 で、石を取る手や近接する弱い相手石への働きかけでなければ、着手後 3 手まで捕獲を読みます。攻め側は捕獲できる手順が一つあればよく、受け側は全合法手とパスを検証します。
- 逃げを発見した場合、深さ制限、候補 384 ノード / 根全体 1,024 ノードの上限に達した場合は未確定とし、除外しません。味方の連絡・救出や石を取る手はこの短手数判定から除きます。
- NN の合法手入力は元のルールどおり。除外は MCTS の根だけに適用します。残った手への 2% 一様事前確率が、除外した手を復活させることはありません。探索 WASM ABI を 2 に更新し、読み込み URL に ABI 番号を付けました。

Benson の固定点については [KataGo の一次実装](https://github.com/lightvector/KataGo/blob/master/cpp/game/board.cpp) の `calculateAreaForPla` も参照しました。曲面の隣接グラフに対する実装です。

## 回帰局面

`v3-tests.mjs` と Rust の単体テストで次を確認しました。

- 全 6 盤で、1 呼吸点の無駄な打ち込みを除外。チェックなしでは、そこを極端に高く評価する入力によって同じ誤着手を再現できます。
- トーラス 7 / 9 / 11 路で、2 呼吸点の閉じた空間への打ち込みを回避。大盤の全ての受けを読むため、途中の開発版の候補上限 192 を最終版では 384 に増やしました。
- 3 呼吸点でも、確実に生きた相手の vital region 内なら除外します。
- 一眼しかない未確定の囲い、逃げ出せる形、大きな囲いの内部は誤って除外しません。
- あえて 1 子を取らせてから 8 子を取り返す捨て石を保持します。通常の取りも保持します。
- 有限ノード数による未確定を「死」としないこと、スーパーコウ・パス・キャンセル・特徴量の既存テストを確認します。

Edge の Worker 内でも WebGPU / WASM の両方で確認しました。2 呼吸点の閉じた領域では 3 点、確実に生きた相手の眼では 6 点を避け、後者では無駄に打たずパスします。推論の数値一致と既存 Worker / UI の回帰テストも通過しました。

## 計算量と対戦

[root-timing.json](data/root-timing.json) は開発用の Node / WASM 観測です。根の履歴復元・全特徴抽出を含み、NN 推論は含みません。ウォームアップ 5 回・測定 20 回。

- トーラス 7 路の 2 呼吸点の閉じた領域：中央値 約 0.028 → 0.105ms。
- トーラス 11 路の同じ形：中央値 約 0.036 → 0.187ms。
- 確実に生きた相手の眼：中央値 約 0.043 → 0.043ms。

並行する開発試走の影響を含む少数の観測であり、端末一般の性能を保証しません。判定は根で一度だけです。

同じ再学習済み NN で、最終版のチェック有無だけを変えた全 6 盤の先後交換対戦（64 simulations、seed 20261203）を [match.json](data/match.json) に保存します。棋力向上を立証する実験ではなく、明らかな回帰を調べる試走です。全結果は summary と棋譜に残します。

チェックあり側は **5 勝 7 敗**、引き分け・打ち切り 0。盤別は球面・小 1 / 2、標準 0 / 2、大 1 / 2、トーラス各サイズ 1 / 2 でした。1 呼吸点・取りなしの自己アタリは 7 回対 14 回でしたが、これには有効な捨て石も含まれるため、無駄な着手の正解ラベルではありません。この少数の対戦から棋力向上は確認できていません。変更の目的は再現局面で根拠のある死に形を除くことであり、勝率改善を根拠にモデルを選び直すことはしていません。

## 再現と限界

ソース差分・ブラウザ観測・対戦・モデル SHA-256 を [manifest.json](manifest.json) と `data/` に記録します。モデルは前回の [再学習](../2026-10-21-strength/README.md) と同じものです。途中の開発版で行った少数の対戦は、最終版の棋力評価に使いません。

```powershell
node tools/ai-gnn/build.mjs
node v3-tests.mjs
node tools/ai-gnn/test-browser.mjs
node tools/ai-gnn/bench-tactics.mjs
node tools/ai-gnn/match.mjs --a dist/models/v3 --b dist/models/v3 --a-tactics safe --b-tactics none --pairs 1 --simulations 64 --seed 20261203 --output tools/ai-gnn/target/tactics-validated-match.json
```

複雑な攻め合い、長いシチョウ、既にある死に石への継ぎ足しの全判定は対象外です。具体的な指摘局面の棋譜はまだ受け取っていないため、この変更は典型的な再現局面による対策です。
