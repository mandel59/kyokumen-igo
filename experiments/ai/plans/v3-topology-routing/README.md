# 盤種ごとの固定モデル切替の検証

2026年10月29日、新しい対局を見る前に登録する。[plan.json](plan.json) を数値条件の正本とする。

共有モデルでは、新規データ追加が平面18/24点・曲面23/48点、completed-Qが平面11/24点・曲面31/48点となり、双方とも全盤の基準に届かなかった。この結果は開発用の選択情報に限り、異なる実験の得点を足して強さを主張しない。

候補を1つに固定する。平面7/9/11路は保存済みNewData-r0、球3/4/5とトーラス7/9/11路は保存済みCompletedQ-r0を使う。盤種以外の条件では切り替えず、重みを追加学習しない。新しいseedの開発72局と、通過時のみ独立432局で評価する。

1手あたりは従来と同じ120,905パラメータ・64訪問・FPU1。保存するモデルは2本になるが、実行中のプレイヤーは最大1本とし、切替時にキャンセル・待機・破棄を行う。既存の単一モデルmanifestでは従来の動作を保ち、子モデルのハッシュを固定する。新モデル資産は採用条件を満たすまで配信スロットに置かない。

開発は40/72点以上、各盤3/8点以上、平面・曲面各50%以上。独立採用は全体55%以上、ペアを保った盤別bootstrap95%区間下限50%超、各盤19/48点以上、平面・曲面各50%以上。候補差し替え・追加対局・既存独立評価の再利用はしない。

正確性は全9盤のCPU/WebGPUで直接の子モデルと選択・出力が一致すること、キャンセルと切替競合、実Workerの経路、全棋譜再生を確認する。暖機後のP95は全体1.05倍・各盤1.10倍以下、ストレスはmax(基準1.10倍、基準+2ms)以下。2モデル化の初期読み込み・切替も5回測り、P95がmax(基準1.5倍、基準+250ms)以下を必要とする。転送サイズは明記し、実機未測定のスマートフォンの性能を主張しない。

通過すればローカルのv3資産を統合する。pushや公開サイトへのデプロイはこの実験に含めない。

## 実行結果（2026年10月29日）

開発72局は43勝29敗（平面16勝8敗、曲面27勝21敗）で全条件を通過した。独立432局は238勝194敗、勝率55.09%、先後ペアを保つ盤別層化bootstrap95%区間は50.69〜59.49%。平面80勝64敗、曲面158勝130敗で、登録した強さの条件をすべて通過した。

各盤48局のうち球面4は20勝28敗、平面7は19勝29敗だった。盤面ごとの差は残るため、全体の成績と合わせて保存した。開発・独立の504局・48,962手を全て再生監査し、打切りは0局だった。

通常時・ストレス・初期化／切替の速度条件もCPU/WebGPU双方で通過した。通常局面P95の基準比はwasm 1.029倍、webgpu 1.007倍。初回平面のP95はCPU約594ms（基準525ms）、WebGPU約324ms（基準238ms）。デスクトップPCでの測定であり、実機スマートフォンの速度は未検証である。

1手は120,905パラメータの1モデル・64訪問・FPU1を維持し、保存するONNX+FP32は986,021→1,972,042バイトになった。モデル切替中の同時保持は1プレイヤーに限定する。
