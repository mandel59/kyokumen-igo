# Kyokugo AI v2 の係数調整と盤別採用（2026-10-21）

> 実験記録：v2/2026-10-21-tuning。v1 / v2 はアーキテクチャ名、係数セットと実行方式は別に扱います。
> 生データ・ログと当時のハッシュは内容を変えずに `data/` へ移しました。履歴中のパスと実行時点のコードは [manifest.json](manifest.json) から追跡できます。
> 当時のコマンドと測定値は履歴です。現在の配置での実行・再集計は [ツールの使い方](../../../../tools/ai-tuner/README.md) を参照し、当時の性能を再測定する場合は記録されたソース版も固定してください。

探索量を固定して係数を自己対局で調整しました。最初の 13 係数の調整では相手・盤への過適合が見つかり、Kyokugo AI v1 も相手に加えて静的評価の 5 係数を追加調整しました。最終候補の対v2-originalの全盤平均は **53.7%（52.4%〜55.0%）**（6,000 局）です。

この値は候補を全盤で使った場合の値です。配信版では事前に定めた盤別の採用基準を適用し、改善を確認できた **トーラス 7×7、トーラス 9×9** に調整値を使います。ほかの盤はv2-originalの 4 手版の係数を維持します。

## 調整方法と、最初の失敗

[search-tune.rs](../../../../tools/ai-tuner/search-tune.rs) は外部クレートを使わない native Rust の交差エントロピー法です。空盤から対局し、先後交換時は AI と乱数系列をセットで交換します。各手に新しい 32-bit seed を使います。各盤でコミ 1・3.5・6.5 を組み合わせます。手数上限は交点数の 20 倍です。

最初は 13 係数を 8 世代×12 候補で探索しました。相手はv2-originalと現最良候補で、上位 3 候補から分布を更新します。探索 6,912 局、別 seed での選定 1,920 局、計 8,832 局、seed 20261025 です。

しかし選定後の検証では、全盤平均でv2-originalに 57.4% 勝っても、球面・大とトーラス 11×11 で大幅に悪化しました。Kyokugo AI v1 への勝率も 42.7% でした。

| 盤 | 最初の候補→v2-original | 最初の候補→v1 |
| --- | ---: | ---: |
| 球面・小 | 73.4% | 66.5% |
| 球面・標準 | 58.1% | 37.5% |
| 球面・大 | 35.2% | 25.0% |
| トーラス 7×7 | 73.4% | 62.5% |
| トーラス 9×9 | 63.3% | 37.5% |
| トーラス 11×11 | 41.1% | 27.0% |

この係数は採用していません。これら 8,400 局の結果を追加調整の方針決めに使ったため、最終候補の独立評価からは除外しています。候補順位を戻す／全係数を半分だけ変更する切り分けも計 480 局実行しました。最初の計画は plan-global.json、結果は diagnostic-* と robust/ablation-* に保存しています。一時検討したサイズ別採用の計画も未実行の記録として残しています。

## 複数相手での追加調整

候補順位をv2-originalに戻し、静的評価の 5 係数を 6 世代×8 候補で調整しました。相手はv2-original・現最良候補・従来のKyokugo AI v1 です。各候補は各相手に 36 局、1 世代の探索は 864 局です。

世代の最良候補を別 seed で各相手に 120 局、さらにv2-original対Kyokugo AI v1 の対照を 120 局、計 480 局で確認します。現最良候補への得点率 53% 超、v2-originalへの得点率 52% 超、Kyokugo AI v1 への得点率が対照より 1 ポイントを超えて下がらず、打ち切りがなければ更新します。この選定も最終評価からは除外します。

追加調整は計 8,064 局、seed 20261040 です。上位 3 候補を使い、標準偏差は前世代 0.6・上位候補 0.4 で平滑化し、探索範囲の 1/60 を下限にします。係数は範囲内に切り詰めて小数 3 桁に丸めてから対局します。初代の候補に切り分けで得た静的評価のみの係数も含めます。

## 最終候補の独立評価と盤別採用

追加調整の完了前に [plan.json](data/plan.json) に未使用 seed・局数・採用規則を記録しました。係数を固定してから最終比較を行い、この seed で係数の選び直しはしていません。

| 最終比較 | 局数 | 候補の得点率（95% 区間） |
| --- | ---: | ---: |
| 候補→v2-original・コミ 6.5 | 6,000 | 53.7%（52.4%〜55.0%） |
| 候補→v2-original・コミ 0 | 600 | 52.8%（48.6%〜56.9%） |
| 候補→v1・コミ 6.5 | 3,000 | 66.9%（65.3%〜68.5%） |
| v2-original→v1の対照・コミ 6.5 | 3,000 | 66.5%（64.9%〜68.1%） |
| 候補→v2-original・コミ 9.5 | 600 | 53.8%（49.8%〜57.8%） |

以下は各盤 1,000 局の対v2-original成績と、同じ seed で各 500 局ずつ測ったKyokugo AI v1 への成績です。

| 盤 | 対v2-original（95% 区間） | 対v1 | v2-original→v1 | 差（ポイント、95% 区間） | 採用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 球面・小 | 55.4%（52.4%〜58.4%） | 72.8% | 74.4% | -1.6（-6.4〜3.2） | v2-originalを維持 |
| 球面・標準 | 53.2%（50.0%〜56.4%） | 66.4% | 64.6% | 1.8（-3.4〜7.0） | v2-originalを維持 |
| 球面・大 | 50.0%（46.8%〜53.2%） | 63.6% | 64.4% | -0.8（-5.7〜4.1） | v2-originalを維持 |
| トーラス 7×7 | 57.2%（54.2%〜60.2%） | 69.2% | 67.6% | 1.6（-3.5〜6.7） | 調整値 |
| トーラス 9×9 | 54.2%（51.1%〜57.3%） | 64.2% | 62.8% | 1.4（-3.7〜6.5） | 調整値 |
| トーラス 11×11 | 52.2%（49.2%〜55.2%） | 65.0% | 65.2% | -0.2（-5.1〜4.7） | v2-originalを維持 |

採用は盤単位で、対v2-originalの先後交換ペア平均の標準誤差を SE として「得点率 − 2.394 × SE > 50%」を要求します。片側有意水準 0.05/6 の Bonferroni 補正で、6 盤の判定全体を扱います。加えて、Kyokugo AI v1 への実測得点率が同じ seed のv2-originalの対照以上で、打ち切りがないことを要求します。

表の 95% 区間はペア平均の正規近似です。Kyokugo AI v1 への差の区間も、同じ乱数組の候補と対照のペア平均の差から計算しています。副条件は実測値による採用ガードであり、Kyokugo AI v1 への形式的な非劣性を証明するものではありません。採用されなかった盤もすべて表示しています。

採用判定は [apply-search-tuning.mjs](../../../../tools/ai-tuner/apply-search-tuning.mjs) で再現でき、[adoption.json](data/adoption.json) に規則・区間・全判定を保存しています。配信版では採用盤だけ係数を変更するため、全盤へ候補を適用した集計勝率を、そのまま配信版の勝率とは扱いません。

最終比較は 13,200 局です。最初の探索・診断・切り分けと追加調整を合わせて計 **38,976 局**、手数上限による打ち切りは 0 局でした。

Windows / AMD Ryzen 7 3700X（16 論理 CPU）、rustc 1.99.0 (b940084d7 2026-09-28)、Node.js v26.7.0 で実行しました。

- 追加の探索・選定：6.17 分（370.231 秒）。

## 検証と再実行

Rust の取り・スーパーコウ・勝敗・引き分け・パス判断・係数の入力検証を確認しました。[search-tests.mjs](../../../../search-tests.mjs) は採用盤には今回の代表棋譜、据え置きの盤にはv2-originalの代表棋譜を使い、計 1,257 手（探索 629 手）について配信 WASM の選択手と JS での再生・得点を照合します。保存・棋譜・Worker・UI の回帰テストと実ブラウザも確認しています。

PowerShell でリポジトリ直下から実行します。

```powershell
node -e "require('node:fs').mkdirSync('tools/ai-tuner/target/search-tuning',{recursive:true})"
rustc --edition 2021 -C opt-level=3 -C lto=fat -C codegen-units=1 -A dead_code tools/ai-tuner/search-tune.rs -o tools/ai-tuner/target/search-tuning/search-tune.exe
.\tools\ai-tuner\target\search-tuning\search-tune.exe robust tools/ai-tuner/target/search-tuning/reproduction 6 8 20261040
.\tools\ai-tuner\target\search-tuning\search-tune.exe match tuned legacy 500 6.5 20261050 tools/ai-tuner/target/search-tuning/reproduction/heldout.json
node tools/ai-tuner/apply-search-tuning.mjs
node tools/ai-tuner/build-wasm.mjs
node search-tests.mjs
node wasm-tests.mjs
node tools/ai-tuner/bench-search.mjs --output tools/ai-tuner/target/search-tuning/performance.json
node tools/ai-tuner/search-tuning-summary.mjs
```

初回 13 係数の探索は robust の代わりに tune、8 世代・12 候補・seed 20261025 を指定します。match は legacy（v2-original）、tuned（全盤に候補）、deployed（採用盤だけ候補）、greedy、または空白区切りの 13 係数ファイルを受け取ります。残りの最終対局条件は plan.json にあります。apply と集計はアーカイブの対局を読み、再実行する場合は同じ形式・配置で結果を揃えます。

[保存データ](data) に全候補の係数・全得点差・選定履歴、最終比較、採用判定、全速度測定値を残しています。[summary.json](data/summary.json) はソースと配信物の SHA-256 も含みます。SEARCH_THREADS 環境変数で並列数を指定でき、スレッド順序で対局結果は変わりません。

今回確認したのは、用意した相手とルールにおける相対的な改善です。人間への棋力や係数の大域的最適性、盤の理論的な適正コミは確定していません。
